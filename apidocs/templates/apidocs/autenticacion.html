Autenticación y Roles

Modelo de usuario

El sistema usa un modelo de usuario personalizado (Usuarios) con email como identificador de login y UUID como PK.

Roles disponibles

RolPermisos
adminAcceso total. Puede asignar roles a usuarios.
medicoAcceso a datos clínicos de pacientes. Puede ver contenido exclusivo para médicos.
odontologoSimilar a médico, con alcance odontológico.
tutorAcceso a sus propios hijos/pacientes a cargo. Solo ve lo que el profesional marca como visible.
ayudanteRol auxiliar con permisos limitados.

JWT (JSON Web Token)

La autenticación usa SimpleJWT. El token incluye los roles del usuario en el payload para autorización stateless (sin consultar la BD en cada request).

Headers

Authorization: Bearer <token>
Content-Type: application/json

Configuración del token

ParámetroValor
ACCESS_TOKEN_LIFETIME60 minutos
REFRESH_TOKEN_LIFETIME1 día
ROTATE_REFRESH_TOKENSTrue
ALGORITHMHS256
AUTH_HEADER_TYPESBearer

Flujo de autenticación

  1. El usuario se registra (/auth/register/, /auth/register-tutor/ o /auth/register-profesional/)
  2. Inicia sesión en /auth/login/ y obtiene un JWT
  3. Envía el token en el header Authorization: Bearer <token> en cada request
  4. El token expira en 60 min; debe renovarse

Nota: Actualmente no hay endpoint de refresh de token implementado. Es un punto pendiente.
